### 2. manifest.json 全フィールド値案

GitHub Pagesのプロジェクトサイト（`https://<user>.github.io/nakano-3d/`）なので、**すべて相対パス**で書く。`scope`/`start_url`/`id` に `/` 始まりの絶対パスを書くとサブパス配信で壊れる（PWA化で最も典型的な事故）。

```json
{

  "short_name": "街カルテ",
  "description": "PLATEAU 3D都市モデルで中野区を眺め、住所や現在地の洪水・土砂災害・用途地域・日照をワンカードで診断するツール",
  "id": "./",
  "start_url": "./?source=pwa",
  "scope": "./",
  "display": "standalone",
  "orientation": "any",
  "lang": "ja",
  "dir": "ltr",
  "theme_color": "#141a22",
  "background_color": "#141a22",
  "categories": ["utilities", "navigation"],
  "icons": [
    { "src": "assets/icons/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "assets/icons/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "assets/icons/icon-maskable-192.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
    { "src": "assets/icons/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

備考:
- `start_url` の `?source=pwa` は計測用（C4のCloudflare Web Analyticsでインストール起動比率が見える）。既存コードはクエリを読まないので無害。
- `display: "standalone"`。3D地図なので `fullscreen` も考えられるが、iOSのステータスバー領域との干渉・戻る操作喪失を避けて standalone にする。
- `orientation` は縦横両対応（地図アプリは横向き利用がある）なので `"any"`。
- `screenshots` フィールド（インストールUIリッチ化）は任意。P3で既存e2eのスクリーンショット成果物を流用して追加してよい。
- `index.html` の `<head>` に追加するタグ: `<link rel="manifest" href="manifest.json">`、`<meta name="theme-color" content="#141a22">`、`<link rel="apple-touch-icon" href="assets/icons/icon-192.png">`（iOSはmanifestのアイコンを見ないため必須）、`<meta name="viewport" ...>` は既存のままでよいが `viewport-fit=cover` を追記し、CSSで `env(safe-area-inset-*)` をボトムシートに適用する。

### 3. Service Worker: キャッシュ戦略

方針: **「アプリの殻は完全キャッシュ、データは鮮度と容量で3分類」**。ROADMAPの「地図タイルは鮮度優先」を精緻化し、ハザード（防災情報＝鮮度が命）だけをネットワークファーストにする。

| 対象 | URLパターン | 戦略 | キャッシュ名 | 上限 |
|---|---|---|---|---|
| アプリシェル | `index.html`, `style.css`, `js/*.js`, `manifest.json`, `offline.html`, アイコン | **precache**（install時に全取得、activate時に旧版削除） | `shell-v{N}` | なし（合計 <300KB） |
| CesiumJS CDN | `cesium.com/downloads/cesiumjs/releases/1.130/**`（Cesium.js本体・widgets.css・実行時に読まれる Workers/Assets/ThirdParty） | **cache-first**（URLにバージョン番号が入っており不変） | `cdn-v1` | 上限なし・ただし用量監視（下記） |
| pbf等CDN | `cdn.jsdelivr.net`, `unpkg.com` | cache-first（バージョン固定URL） | `cdn-v1` | 同上 |
| 背景地図タイル | `cyberjapandata.gsi.go.jp/xyz/**` | **stale-while-revalidate**（航空写真・淡色は更新頻度が低い。表示は即時、裏で更新） | `basemap` | LRU 300エントリ |
| ハザードタイル | `disaportaldata.gsi.go.jp/raster/**` | **network-first**（タイムアウト5秒でキャッシュへフォールバック。防災情報は常に最新を優先、災害時のポータル不安定への保険としてキャッシュを残す） | `hazard` | LRU 200エントリ |
| 用途地域MVT | `assets.cms.plateau.reearth.io/**/*.mvt` | stale-while-revalidate | `zoning` | LRU 100エントリ |
| PLATEAU 3D Tiles | `assets.cms.plateau.reearth.io/**/{tileset.json,*.b3dm,*.glb,*.cmpt,テクスチャ}` | **キャッシュしない（パススルー）** | — | — |
| ページ遷移 | `mode === 'navigate'` | network-first → 失敗時 `offline.html` | — | — |

設計判断のポイント:
- **3D Tilesは意図的にキャッシュ対象外**。中野区LOD2一式は数GB規模で、Cache Storageのオリジン容量（ブラウザ実装依存、iOS Safariは特に厳しい）を確実に食い潰す。Cesium自体がメモリ内タイルキャッシュを持つため、SWで二重キャッシュする利益も薄い。オフライン時の3D表示は「できない」と割り切り、offline.htmlで明示する。
- **LRUパージ**: Cache APIには上限機能がないため自前実装。`cache.put` 後に `cache.keys()` して超過分を古い順に `cache.delete`（キー順序は挿入順であることを利用。厳密なLRUでなく挿入順削除で十分）。加えて activate 時に `navigator.storage.estimate()` をログし、`usage > 0.8 * quota` なら `basemap`/`hazard`/`zoning` を全クリアする防衛線を入れる。
- **キャッシュバージョニング**: `sw.js` 冒頭に `const VERSION = 'v1';`。シェル更新時は VERSION を上げてデプロイ → activate で旧キャッシュ削除。`sw.js` 自体はHTTPキャッシュに乗らないよう、GitHub Pagesのデフォルト（`max-age=600`）で許容（最悪10分遅れで更新される）。
- **更新通知**: `registration.updatefound` → 新SWが `installed` になったら画面下に「新しいバージョンがあります [再読み込み]」トーストを出す（`skipWaiting` を無条件に呼ばない。Cesium動作中のcontroller切替を避ける）。
- **SW登録**（`js/pwa.js`）: `navigator.serviceWorker.register('sw.js')`（相対パス。スコープは自動的に `/nakano-3d/` になる）。`location.search` に `nosw=1` がある場合は登録しない（e2e・デバッグ用）。

### 4. アイコン生成（外部アセットなし）

1. `assets/icons/icon.svg` を手書きで作成。案: `#141a22` の角丸背景 + 高さ色分け配色（`#4575b4`〜`#d73027`、既存凡例と同じ）を使った建物3本のシルエット + 白の位置ピン。テキストは入れない（小サイズで潰れる）。
2. maskable版は同じSVGの別バリアント: 背景を全面ベタ塗り（角丸なし）にし、**モチーフをキャンバス中央80%以内**に収める（maskableセーフゾーン）。
3. PNG化は**既存devDependencyのPlaywrightで行う**（sharp等の依存追加をしない）:

```js
// assets/icons/generate-icons.mjs — node assets/icons/generate-icons.mjs で1回実行し、PNGをコミット
import { chromium } from 'playwright';
// chromium.launch({ executablePath: '/opt/pw-browsers/chromium', args: ['--no-sandbox'] })
// page.setViewportSize({width: 512, height: 512}) → page.goto('file://.../icon.svg')
// → page.screenshot({ path: 'icon-512.png', omitBackground: false })
// 192px は viewport 192 で再実行（縮小ではなく再ラスタライズ）
```

4. 生成したPNG4枚はリポジトリにコミット（ビルドレス原則維持。生成スクリプトは再現手段として同梱）。
5. 検証: https://maskable.app/editor に maskable版をドロップし、minimum safe area で欠けないこと。

### 5. モバイル軽量モードの仕様

判定（`js/pwa.js` に `export function isMobileLike()`）:
```
matchMedia('(pointer: coarse)').matches && min(screen.width, screen.height) < 820
|| navigator.deviceMemory !== undefined && navigator.deviceMemory <= 4
```

適用値（`js/config.js` に `QUALITY_PROFILES` として定数化し、`main.js` の `getTileset()` とViewer初期化で参照）:

| パラメータ | 既定（PC） | 軽量モード（モバイル初期値） | 高画質モード（設定で切替） |
|---|---|---|---|
| 初期建物レイヤー | LOD2 | **LOD1** | LOD2 |
| `maximumScreenSpaceError` | 16 | **24** | 16 |
| `cacheBytes`（Cesium3DTileset） | 既定512MB | **128MB**（`maximumCacheOverflowBytes: 64MB`） | 既定と同じ512MB |
| `dynamicScreenSpaceError` | false | **true** | 既定と同じfalse |
| `viewer.resolutionScale` | 1.0 | **1.0**（`useBrowserRecommendedResolution` は既定trueのまま＝CSSピクセル解像度） | 既定と同じ1.0 |
| `scene.requestRenderMode` | false | **true**（`maximumRenderTimeChange: 0.5`。カメラ静止時に描画を止め電池消費とGPUメモリ圧を削減。影スライダー操作時は `scene.requestRender()` を明示発火） | 既定と同じfalse |

- UI: 左パネル「建物モデル」節の下に「表示品質: ● 軽量（推奨） / ○ 高画質」ラジオを追加。選択は `localStorage` に保存。高画質選択時に iOS では注意文「メモリ制限により強制再読み込みされる場合があります」を表示。
- 根拠（2026-07時点の公知情報）: iOSのWebContentプロセスはjetsam機構で強制終了され、iPhoneでの上限は約2GB（ActiveHard 2048MB）、ページ実効では300〜450MB程度が安全圏とされる（[Deep Dive: RAM Internals in WebKit](https://www.catchmetrics.io/blog/deep-dive-ram-internals-webkit)）。CesiumはiPhone SE等でWebGLコンテキストロストによるクラッシュ報告があり（[Cesium Community](https://community.cesium.com/t/cesium-crashes-iphone-se-context-lost-webgl/16961)）、iOS 18.2/18.3ではWebGLコンテキストロストの退行も報告された（[Apple Developer Forums](https://developer.apple.com/forums/thread/778735)）。→ LOD2テクスチャ付き（数百MB級）をモバイル既定にしない判断は妥当。WebGL2自体はiOS 15以降のWKWebView/Safariで利用可能でCesium 1.130は問題なく動く。
- `scene.canvas` の `webglcontextlost` イベントをハンドルし、「メモリ不足のため表示をリセットします」表示 → 軽量モードに落とし、URLの`quality`指定を除去して`location.reload()`。

### 6. ボトムシートUI（診断カード）

現状 `#diagnosisPanel` はモバイル幅で右側パネルのまま。768px未満では**ボトムシート**に切り替える。

- 実装: CSS（`@media (max-width: 767px)` で `#diagnosisPanel` を `position: fixed; left:0; right:0; bottom:0; border-radius:16px 16px 0 0; padding-bottom: env(safe-area-inset-bottom);` に）+ `js/bottomsheet.js`（約120行想定）。
- 3状態スナップ: **peek**（高さ140px、地点名と洪水バッジだけ見える）/ **half**（50vh、既定）/ **full**(88vh)。状態は `transform: translateY()` + `transition 0.25s` で切替。
- ドラッグ: シート上部に `.sheet-handle`（幅40px高さ4pxのバー、`touch-action: none`）。`pointerdown/move/up` で追従し、離した位置と速度で最寄り状態へスナップ。下方向へpeek超えでスワイプしたら `diagnosis.close()`。
- 地図操作との干渉: シート本体は `touch-action: pan-y`、シート内スクロール（診断カードが長い）は full 状態でのみ `overflow-y: auto` を有効化。
- アクセシビリティ: `role="dialog"` `aria-label="街カルテ 診断結果"`、ハンドルに `role="button"` `aria-label="シートを開閉"`。閉じるボタンは既存 `#closeDiag` を維持。
- `diagnose.js` 側の変更は最小: パネルopen時に `document.body.classList.add('sheet-open')` を足す程度。DOM生成ロジックは触らない。

### 7. オフライン時フォールバック（offline.html）

- precacheに含める完全自己完結の1ファイル（CSSインライン、画像なし）。内容: アイコン（インラインSVG）＋「オフラインです。3D地図と診断には通信が必要です」＋[再読み込み]ボタン＋豆知識として「公式ハザードマップは災害時に紙でも確認を」の一文。
- SWの navigate ハンドラでのみ使用。fetch失敗したタイル等は各モジュールの既存エラーハンドリング（「取得できませんでした」表示）に任せ、SWは黙って失敗を返す。

### 10. 既存e2eへの影響（重要）

- **Playwrightの `page.route()` はService Worker発のリクエストを傍受できない**。curl中継ハーネス（`test/harness.mjs`）が機能しなくなるため、次の2段構えにする:
  1. e2eのページURLに常に `?nosw=1` を付与し、アプリ側で登録スキップ（P1で実装）。
  2. 保険として `browser.newContext({ serviceWorkers: 'block' })` をharnessに追加（Playwright標準オプション）。
- SW自体のテストは「登録される」「precache一覧にshellファイルが全部ある」ことを検証する軽い専用テスト（`test/sw.test.mjs`: sw.jsを文字列読込して precache配列と実ファイル一覧を突合）に留める。オフライン動作は手動確認項目とする。
- **precache一覧の更新漏れ**が今後の典型バグになるため、`test/sw.test.mjs` の突合テストをCI（R6）に含める。

## R8b. Capacitorストア配信（工数: M＋手動作業 / 依存: R8a・R7-C1 / リスク: 中）

### 1. 前提と最新バージョン（2026-07時点）

- **Capacitor 8 が最新メジャー**。要件: **Xcode 26.0+ / iOSデプロイメントターゲット15.0 / Android Studio Otter (2025.2.1)+**。出典: [Updating to 8.0 | Capacitor Docs](https://capacitorjs.com/docs/updating/8-0)、[Capawesome: How to Upgrade to Capacitor 8](https://capawesome.io/blog/how-to-upgrade-your-capacitor-app-to-capacitor-8/)。
- Appleは **2026-04-28以降、App Store Connect へのアップロードに Xcode 26 / iOS 26 SDK ビルドを必須化**済み。よってmacOS環境（Xcode 26が動くMac）が必須。出典: [Capgo: Xcode 26 Requirement](https://capgo.app/blog/xcode-26-requirement-for-capacitor-apps/)。
- WKWebViewのWebGL2はiOS 15+で問題なし。メモリ制限はSafariと同じjetsam支配下（第1部§5参照）なので、**アプリ版でも軽量モードを既定にする**。

### 2. モノレポ構成と初期化手順

```
/            … Webアプリ本体（SSoT。GitHub Pagesにもデプロイ）
/mobile/     … Capacitorシェル（独立したpackage.json。ルートのビルドレス原則を汚さない）
  package.json
  capacitor.config.ts
  www/       … sync-web.mjs が生成（gitignore）
  ios/ android/ … npx cap add が生成（コミットする）
  sync-web.mjs … ルートの index.html, js/, style.css, manifest.json, assets/ を www/ にコピー
```

初期化コマンド（ユーザーまたはOpusが実行）:

```bash
mkdir mobile && cd mobile
npm init -y
npm i @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android @capacitor/geolocation
npx cap init "街カルテ" "jp.<取得ドメイン逆順>.machikarte" --web-dir www   # appIdはC6のドメイン取得後に確定
node sync-web.mjs
npx cap add ios
npx cap add android
npx cap sync
```

設計判断: `server.url` でGitHub Pagesを読み込む「リモートシェル」方式は採らない（審査ガイドライン4.2リスク増・オフライン起動不能）。**Web資産をwwwに同梱**し、データは従来どおり実行時取得。

### 3. ネイティブ権限

| 機能 | iOS (`ios/App/App/Info.plist`) | Android (`android/app/src/main/AndroidManifest.xml`) |
|---|---|---|

### 2-2. Cloudflare R2 + 独自ドメイン配信手順

前提契約: Cloudflareアカウント（無料プランで開始可）+ 独自ドメイン（C6。年約1,500〜2,000円）。ドメインのDNSをCloudflareに移す（カスタムドメイン接続に必要）。

1. **バケット作成**: ダッシュボード > R2 > Create bucket。バケット名 `plateau-tiles`。ロケーションAPAC。
2. **バケット構成**（年度更新を見越したパス設計）:
   ```
   plateau-tiles/
     nakano/2025/bldg_lod1/tileset.json, ...   ← 配布zipを展開したツリーをそのまま
     nakano/2025/bldg_lod2/...
     nakano/2025/fld_kanda_l2/... ほか config.js のTILESETSと1:1
     nakano/2025/urf_use_mvt/{z}/{x}/{y}.mvt   （2-1で入手できた場合）
   ```
3. **アップロード**: ファイル数が万単位になるため rclone を使う（S3互換API・R2のAPIトークンを発行）:
   ```bash
   rclone config  # type=s3, provider=Cloudflare, access_key/secret= R2 APIトークン, endpoint=https://<account_id>.r2.cloudflarestorage.com
   rclone copy ./nakano_2025_3dtiles r2:plateau-tiles/nakano/2025 --transfers 32 --checksum
   ```
4. **検証**: アップロード後、ローカルで `js/config.js` のTILESETSを一時的にR2 URLへ向け、既存e2e一式（スモーク+診断）を実行して全パスを確認。
5. **カスタムドメイン接続**: R2 bucket > Settings > Custom Domains > `tiles.<ドメイン>` を追加（Cloudflareが自動でDNS/TLS設定）。公開は必ずカスタムドメイン経由（`r2.dev` の開発URLはレート制限がありCDNキャッシュも効かないため本番使用しない）。
6. **CORS設定**: bucket > Settings > CORS policy:
   ```json
   [{ "AllowedOrigins": ["https://<user>.github.io", "https://<本番ドメイン>"],
      "AllowedMethods": ["GET", "HEAD"], "AllowedHeaders": ["*"], "MaxAgeSeconds": 86400 }]
   ```
7. **キャッシュヘッダ**: Cloudflare > Rules > Cache Rules で `tiles.<ドメイン>/*` を Cache Everything + Edge TTL 30日。タイル実体（b3dm等）は不変なので `Cache-Control: public, max-age=31536000, immutable` をメタデータで付与（rclone `--header-upload`）。`tileset.json` のみ `max-age=3600`（年度差し替え時の反映用）。
8. **config切替**: `js/config.js` のTILESETSを新URLへ。旧URL（plateau.reearth.io）はコメントで残す。フォールバック実装（新URL 404/timeout時に旧URLへ）はSサイズで追加可能、推奨。
9. **年度更新の運用**: `nakano/2026/...` を並行アップロード → e2e確認 → config切替 → 旧年度は3ヶ月後に削除。この手順を `docs/ops-tiles.md` としてスクリプト（rcloneコマンド）付きで残す。

### 2-3. ハザードタイルのWorkersキャッシュ中継（コード骨子）

目的: 平常時のレイテンシ改善＋災害時のdisaportal集中アクセス時の可用性向上。Workers無料プランは10万リクエスト/日（出典: [Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/)）で当面十分。

エンドポイント: `https://hz.<ドメイン>/raster/<layer>/{z}/{x}/{y}.png`

```js
// workers/hazard-cache/src/index.js — 骨子
const ALLOW = /^\/raster\/(01_flood_l2_shinsuishin_data|01_flood_l2_keizoku_data|05_dosekiryukeikaikuiki|05_kyukeishakeikaikuiki|05_jisuberikeikaikuiki)\/\d+\/\d+\/\d+\.png$/;

export default {
  async fetch(req, env, ctx) {
    const url = new URL(req.url);
    if (!ALLOW.test(url.pathname)) return new Response('forbidden', { status: 403 });

    const cache = caches.default;
    const cacheKey = new Request(url.toString());
    let res = await cache.match(cacheKey);
    if (!res) {
      const origin = await fetch('https://disaportaldata.gsi.go.jp' + url.pathname,
                                 { cf: { cacheTtl: 86400 } });
      // 404（=区域外タイル）もキャッシュする。5xxは10分だけ負キャッシュして origin を守る
      res = new Response(origin.body, origin);
      res.headers.set('Cache-Control', origin.ok || origin.status === 404
        ? 'public, s-maxage=86400, stale-if-error=604800'   // TTL1日+障害時7日stale
        : 'public, s-maxage=600');
      res.headers.set('Access-Control-Allow-Origin', '*');
      res.headers.set('X-Data-Source', 'disaportaldata.gsi.go.jp');
      res.headers.set('X-Fetched-At', new Date().toISOString());
      ctx.waitUntil(cache.put(cacheKey, res.clone()));
    }
    return res;
  }
};
```

- デプロイ: `npm create cloudflare@latest workers/hazard-cache` → `wrangler deploy` → カスタムドメインルート `hz.<ドメイン>/*` を割当。
- アプリ側: `js/config.js` の `HAZARD_TILES.*.url` のホストを差し替え、UIの出典表記に「取得日時（X-Fetched-At）・出典: ハザードマップポータルサイト」を表示（鮮度の可視化、ROADMAP要件）。
- 静的ホスティング自体の移行（GitHub Pages → Cloudflare Pages）はリポジトリ接続のみで完了（ビルドコマンド無し・出力ディレクトリ`/`）。商用ドメインを載せる段階で実施。

# 第3部 R5: AI連携（BYOK方式・実験的機能）

**工数: M / 依存: R1（比較があると価値増、必須ではない）/ 方針: `?ai=1` フラグでのオプトイン公開**

ROADMAPの選択肢a（BYOK）を採用し、将来b（Workers中継）へ移行できる形で設計する。「APIキー不要」原則の例外であることをUI上でも明示する。

## 1. APIキーのlocalStorage保存UI

- 左パネルに新セクション「AI要約（実験的）」。**URLに `?ai=1`（または `#ai=1`）がある場合のみ表示**。
- 構成: `<input type="password" id="aiKey" placeholder="sk-ant-...">` + [保存] + [削除] + モデル選択（§4）+ 注意文。
- 保存先: `localStorage['nakano3d.ai.key']`（保存時に `sk-ant-` プレフィックスを軽く検証）。モデル選択は `nakano3d.ai.model`。
- 注意文（必須表示）:「APIキーはこの端末のブラウザ内にのみ保存され、Anthropic社のAPI以外には送信されません。共有端末では保存しないでください。利用量に応じてAnthropicから課金されます（目安: 1診断あたり数円、§5）」。
- 診断カード末尾に「🤖 AI要約を生成」ボタン（キー未設定時は設定セクションへの誘導文）。

## 2. Anthropic Messages APIのブラウザ直叩き

ビルドレス構成のため公式SDKは使わず、`fetch` で直接呼ぶ（`js/ai.js` 新規、約150行）。CORSは Anthropic が提供する **`anthropic-dangerous-direct-browser-access: true`** ヘッダで許可される（このヘッダ名自体が「キーがブラウザに露出する」ことへの警告であり、BYOK＝ユーザー自身のキーだから許容できる、という整理をコードコメントに残す）。

```js
// js/ai.js — 骨子
export async function summarize(diagnosis, { apiKey, model }) {
  const res = await fetch('https://api.anthropic.com/v1/messages', {
    method: 'POST',
    headers: {
      'x-api-key': apiKey,
      'anthropic-version': '2023-06-01',
      'anthropic-dangerous-direct-browser-access': 'true',
      'content-type': 'application/json',
    },
    body: JSON.stringify({
      model,                       // 既定 'claude-opus-5'（§4）
      max_tokens: 1024,
      system: SYSTEM_PROMPT,       // §3
      messages: [{ role: 'user', content: buildUserPrompt(diagnosis) }],
    }),
  });
  if (!res.ok) throw await toAiError(res);   // 401=キー不正/429=レート/529=過負荷 を日本語文言に変換
  const data = await res.json();
  if (data.stop_reason === 'refusal') throw new AiError('生成が拒否されました');
  return data.content.filter((b) => b.type === 'text').map((b) => b.text).join('');
}
```

- 入力データは `diagnose.js` の `getLastResult()`（座標・洪水ランク・土砂3種・用途地域/建蔽/容積/防火/高度・日照3日付・最寄り避難所(R2後)）をJSON整形して渡す。**タイル画像等は送らない**（トークン節約・プライバシー）。
- ストリーミング（SSE）は初版では見送り、`max_tokens: 1024` の一括受信＋スピナーで十分（応答5〜15秒想定）。A2改善候補。
- e2e: `api.anthropic.com` をharnessの中継対象に**追加しない**。e2eではモックしたfetch応答（`page.route` はSW非経由の通常fetchなので傍受可能）で「ボタン→スピナー→本文表示」だけ検証する。

## 3. プロンプト設計（システムプロンプト案）

```
あなたは日本の住環境アドバイザーです。中野区の地点診断ツール「街カルテ」が出力した
公的データ（洪水浸水想定・土砂災害警戒区域・用途地域・日照シミュレーション）のJSONを受け取り、
一般の住まい探し中のユーザー向けに日本語で要約・解説します。

守るべきルール:
1. 与えられたJSONに含まれる事実のみを根拠にする。含まれない情報（治安・地価・騒音など）を推測で述べない。
2. 「安全です」「危険です」のような断定をしない。「〜の想定区域に含まれています」等、データの記述に留める。
3. 数値（浸水深ランク・建蔽率・容積率・日照時間）は必ず原文どおり引用する。
4. 本ツールは宅地建物取引業法の重要事項説明には使用できない参考情報であることを踏まえ、
   重要な判断は公式ハザードマップ・自治体窓口の確認を促す一文を必ず末尾に入れる。
5. 出力形式: 全体400〜600字。「■まとめ」(2〜3文) →「■観点別」(・防災 ・建築の制限 ・日当たり の3項目、
   各1〜2文) →「■こんな人は要確認」(1〜2文。例: 小さい子がいる家庭、車いす利用、在宅勤務) → 確認促し。
6. 診断項目が「判定不能」「取得できませんでした」の場合はその旨を正直に伝える。
```

ユーザープロンプト（`buildUserPrompt`）は「以下は地点『{title}』(東経{lon}, 北緯{lat})の診断結果JSONです。ルールに従って要約してください。」+ JSONコードブロック。比較機能（R1）実装後は2〜3地点分のJSONを並べ「比較の観点で」と指示を足すバリアントを追加。

## 5. 免責UI

## 6. 将来のWorkers中継方式への移行パス

- `js/ai.js` の呼び出し面を `summarize(diagnosis, opts)` に固定し、内部でエンドポイントを分岐: `config.AI = { mode: 'byok' | 'relay', relayUrl: 'https://api.<ドメイン>/ai/summarize' }`。
- relay側（C2/C3と同じWorkersプロジェクト）: `POST /ai/summarize` に診断JSONを受け、Workers内で同一のシステムプロンプト＋`ANTHROPIC_API_KEY`（wrangler secret）でMessages APIを呼ぶ。悪用対策: WAFレート制限（IPあたり10回/日）+ 入力サイズ上限8KB + モデル固定。
- プロンプト・モデル・出力整形はBYOKと共通化（`js/ai-prompt.js` に分離しWorkersへコピー同期）。移行時のクライアント変更はconfig 1行。
- 移行判断の目安: 一般公開して「キーを持たないユーザーに使わせたい」となった時点。月間1,000診断でも relay原価は $20前後（opus-5）であり、C5の収益化と抱き合わせで判断する。
