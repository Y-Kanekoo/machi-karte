# 実装計画 R-UX (v2.2): 体感チューニング（フィードバック・モバイル・動線）

作成: 2026-08-03 / 計画: Claude (Fable) / 実装: Codex gpt-5.6-sol（確立済みパイプライン）
規範: `docs/design/DESIGN-GUIDELINES.md`（全フェーズ必読）/ 調査根拠: `docs/design/UX-RESEARCH.md`

## ねらい

機能は揃った（v1.3〜v2.1）が体感が伴っていない3点を引き上げる:
①操作フィードバック（無反応・状態不明の全廃） ②モバイル体感（シートと地図の一体感） ③動線（2タップ規範）。
見た目の色・質感の刷新はスコープ外（トークン整備の副次改善はあり得る）。

## フェーズ

| フェーズ | 内容 | DoD |
|---|---|---|
| **P0 計測ベースライン** | LoAF/INP軽量自前計測（Event Timing + PerformanceObserver、数十行）を `window.__nakano.perf` テストフックに常設。主要7操作（検索診断・地図タップ診断・階数変更・日影開始/中断・レイヤー切替・シート操作・エリア切替）の現状INP・LoAF数・スクショ/GIFを記録し本計画書に追記 | 計測フック単体+e2e。ベースライン数値の記録完了 |
| **P1 フィードバック・モーション** | デザイントークン導入（§2の体系、既存transition/animationを全てトークン参照に置換）・reduced-motion一括対応・診断カードのスケルトン表示・全ボタンの押下状態・200ms/1秒規範の適用漏れ修正・結果出現のハイライト・requestRender発火の総点検 | 既存全e2e無改変パス+新規e2e（reduced-motionでアニメ0・スケルトン表示・押下状態）。**GIF提示→ユーザー体感確認** |
| **P2 動線** | 「現在地を診断」FAB（モバイル）・左パネルの使用頻度順再配置と折りたたみ既定の拡大・診断カード内の主要アクション（共有・比較・階数）の到達タップ数削減 | 2タップ規範のe2e検証。**スクショ提示→ユーザー体感確認** |
| **P3 モバイル磨き** | シート×地図連動（注視点オフセット）・シートドラッグの追従性/慣性閾値チューニング・タッチターゲット44px総点検 | モバイルe2e+実機チェックリスト更新。**GIF提示→ユーザー体感確認** |
| **RC** | 統合レビュー（Codex）→修正→P0比の計測差分を記録→PR | 全テストグリーン・INP/LoAFがP0比で悪化なし（主要操作は改善） |

体感確認ゲート: P1/P2/P3の各完了時に SendUserFile でスクショ・GIFを提示し、**ユーザーのOKを得てから次フェーズへ**（従来の全自動進行とここが異なる）。

## 制約

- ビルドレス維持・外部依存追加禁止（web-vitalsライブラリは採用せず自前数十行で計測）・Cesium 1.130固定
- 既存e2e（92/123/74/50/83/43）は原則無改変パス・既定挙動の互換（表示タイミングの改善は可、情報・機能の削除は不可）
- **改訂（2026-08-03 / P2停止判断を受けて）**: 承認済みUX変更（パネル折りたたみ既定化）に伴い、既存e2eへの変更を「操作前に対象セクションを開くセットアップステップの追加」に限り許可する。**アサーション（検証内容）の変更・削除・緩和は引き続き禁止**。共通ヘルパー（openSection等）で変更を最小化し、変更した項目は全件を実装報告に列挙する
- CSS変更はトークン経由のみ（直書きduration/easing禁止）。sw.js precache/VERSION更新を忘れない
- 性能の数値目標はCIでassertしない（CIは機能・実機は性能の線引きを維持。計測フックは記録用）

`test/output/rux-baseline.json`（コミット外・再計測可能）。LoAFカウントはセッション累積のため**操作別増分**で読む:

| 階数セレクタ変更 | 320 | +15 |
| 日影開始→中断 | 320 | +34 |
| レイヤー切替 | 320 | +0 |
| エリアセレクタ開閉 | 320 | +2 |
| モバイルシート遷移 | 248 | 5（別セッション） |

## リスク

| リスク | 対策 |
|---|---|
| トークン置換で微妙なタイミング差→既存e2eのアニメ待ちが壊れる | e2eはアニメ完了待ちでなく状態待ちが既存流儀。P1で崩れたら実装側で待ち条件を状態化 |
| シート×地図連動がカメラ操作と競合 | ユーザー操作中はオフセット適用を停止（moveEnd後のみ）。診断flyToとの合成はP3で実測して決定 |
| requestRender総点検の漏れ | P0の計測フックで「操作後にフレームが出たか」をe2eで機械検出 |
