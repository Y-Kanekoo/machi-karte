1. 神田川沿い（南台）を診断すると、洪水セクションに「浸水想定 0.5〜3.0m／**浸水が引くまでの目安: 12時間未満**／計画規模でも 0.5〜1.0m」が並び、水害リスクの「深さ×時間」が一目で分かる。
2. 同じカードに「**最寄りの震災時避難所: 南台小学校 約440m**（直線距離）」が出て、地図の避難所ピンをONにすると区内全避難所が種別色分けで見える。

## 2. 機能要件と受け入れ基準

### F2-1. 浸水継続時間（カード表示）
- `01_flood_l2_keizoku_data` タイル（z=16）を色判定し、洪水セクションに「浸水継続時間（浸水が引くまでの目安）」行を追加。
- ランク: 12時間未満 / 12時間〜1日 / 1日〜3日 / 3日〜1週間 / 1週間〜2週間 / 2週間〜4週間 / 4週間以上（§3.1の実測凡例）。
- 透明・404は「データなし」。表示ルール: 洪水ランクが「区域外」なら「―」、洪水ランクありで継続時間が透明なら「データなし」と区別する（弥生町二丁目が後者の実例。§3.1）。
- 凡例注記（重ねるHM原文）: 「2週間以上〜」の色は自治体により「4週間以上〜」を意味する場合がある → ランク名は「2週間〜4週間（自治体により2週間以上）」の注記をカードのnoteに入れる。
- **受け入れ基準**: 南台五丁目 (139.663, 35.688) で「12時間未満」、中野五丁目 (139.66893, 35.707859) で「―」が表示される（e2e）。

### F2-2. 内水氾濫（スコープアウト＋注記）
- **調査結果（2026-07-27実測、§3.2）: 中野区の内水タイルは重ねるハザードマップに配信なし**。PLATEAUにも中野区の内水モデルなし。代替データ（東京都下水道局CSV）は前処理が重く費用対効果が低い。
- 実装は注記のみ: 洪水セクション末尾に「内水（雨水出水）の浸水想定は本ツール未対応です。中野区の水害ハザードマップをご確認ください」（リンク先は実装時に現行URLを確認）。
- **受け入れ基準**: 注記とリンクがカードに常時表示される。

### F2-3. 避難所・避難場所レイヤーと「最寄り避難所」
- データ: 中野区オープンデータ3種（震災時の避難所一覧45件・水害時避難所44件・広域避難場所13件、いずれもCC BY 4.0・経緯度付き。§3.3）を前処理して `data/shelters.geojson` に同梱。`npm run shelters` で再生成可能にする。
- 3D地図: 左パネル「防災・その他レイヤー」に「避難所・避難場所」トグル。種別で色分けした点Entity＋ラベル（震災時=緑 / 水害時=青 / 広域=橙。billboard画像は使わない）。ラベルは近距離のみ表示（`distanceDisplayCondition`）で102件の描画負荷とラベル重なりを抑える。
- 診断カード: 新セクション「🏫 避難所」に「最寄りの震災時避難所」「最寄りの水害時避難所」各1件（名称＋約○m）を表示し、「※直線距離です。経路距離・開設状況は区の発表をご確認ください」を注記。
- **受け入れ基準**: 弥生町二丁目の診断で「第二中学校 約260m」（震災時）が表示される。レイヤーONでピンが100件前後表示される（e2e）。

### F2-4. 浸水深の3D表現
- 洪水セクションに「💧 浸水深を3Dで表示」トグルボタン。ONで診断地点周辺（半径150m）に半透明水面の円柱（`EllipseGraphics`、`height`=地面高さ、`extrudedHeight`=地面+浸水深上限）を表示。
- 使う深さ: 既存 `queryFlood` が返す `depthMax`。「20.0m以上」は20mでキャップし「（20m超）」を注記。「区域外／判定不能」時はボタンを無効化。
- 地面高さ: 既存 `estimateBaseHeight`（js/sunlight.js）を再利用。
- カード上に説明: 「左パネルの洪水レイヤー（PLATEAU）は区全域の想定を面で表示します。この水面は診断地点の想定浸水深の上限を柱状に示した目安です」。
- カードを閉じたら水面Entityも消す（既存 `onClose` フック）。
- **受け入れ基準**: 南台五丁目で水面が表示され、`viewer.entities` に該当Entityが存在（e2e）。スクリーンショットで建物と水面の高さ関係が視認できる。

### F2-5.（任意）洪水浸水想定・計画規模
- `01_flood_l1_shinsuishin_newlegend_data`（z=16、中野区配信あり・2026-07-27実測）を色判定し、洪水セクションに「計画規模（おおむね30〜100年に1回程度）: 0.5〜1.0m」行を追加。
- 新凡例は細分色（〜0.3m / 0.5〜1.0m）を含む（§3.1）。
- **受け入れ基準**: 南台五丁目で「0.5〜1.0m」、弥生町二丁目で「区域外」（e2e）。
- 時間が押したら本項目のみ落としてよい。

### 3.2 内水氾濫の調査ログ（結論: 中野区は配信なし）

- ROADMAPの `01_naisui_data` は**プレフィックス誤り**。正しくは `02_naisui_data`（統合版）と `02_naisui_pref_data/{都道府県コード}/`。出典: https://disaportal.gsi.go.jp/hazardmap/copyright/opendata.html（2026-07-27取得）。提供開始 令和5年12月20日。
- **中野区は両パスとも404**: z=16代表7タイル×2パス全て404、z=14で中野区全域を覆う30タイルも全て404（2026-07-27実測）。
- 掲載市町村一覧 https://disaportal.gsi.go.jp/hazardmap/copyright/csv/naisui.csv（62市町村）に**中野区なし。東京都は昭島市・福生市の2市のみ**。統合版タイルは武蔵野・多摩方面に200が存在することも確認（データ自体は生きている）。
- PLATEAUカタログでも中野区17データセット中に内水モデルなし。
- 代替候補の評価:
  - 東京都下水道局「浸水予想区域図 浸水深・地盤高データ」CSV: 神田川流域・北側だけで**27.3MB**の10mメッシュ点データ。静的サイト同梱の規模を超え、既存の洪水L2表示と重複が大きい → **不採用**。
  - 中野区オープンデータの「浸水深」「浸水継続時間」CSV（wagmap）: **ランクごとの代表点1個ずつの凡例アノテーションデータ**で面判定には使えない → 不採用（Opusが誤って追いかけないこと）。
- **結論: F2-2は「配信なし」でクローズし、§2.2の注記表示のみ実装**。将来、naisui.csvに中野区が載ったら `HAZARD_TILES` に1エントリ追加するだけで対応できるよう、hazard.jsの実装は汎用のままにしておく。

### 3.4 前処理スクリプト仕様（tools/fetch-shelters.mjs）

1. 上記3URLをfetch（ユーザーの手元でも動く素のfetch実装。依存を増やさない）
2. BOM除去→引用符対応CSVパース（自前実装30行程度）
3. 検証: 件数>0、経度139.5〜139.8・緯度35.6〜35.8の範囲チェック、名称非空。範囲外行は警告して除外
4. `data/shelters.geojson` を生成。`metadata` に generated/license/attribution/sources（URL+取得日）を必ず埋める。`properties.type` は `quake` / `flood` / `wide`。同名施設が複数種別にある場合もマージせず別Featureとして持つ
5. `package.json` に `"shelters": "node tools/fetch-shelters.mjs"` を追加。README に出典・取得日・ライセンス・再生成手順を明記

設計メモ:
- hazard.jsの拡張は既存パターンの複製で済む。keizoku/L1を足しても診断1回あたりのタイル取得は最大+2枚。
- 避難所Entityは専用 `Cesium.CustomDataSource`（`viewer.dataSources`）に入れる。表示切替が `dataSource.show` 一発になり、診断ピンとの干渉・close時の誤削除を防げる。ラベルは `DistanceDisplayCondition(0, 2500)` で近景のみ。
- `nearestShelter` は102件の線形走査で十分。空間インデックスは入れない。
- floodviz は絶対高（`height: baseHeight, extrudedHeight: baseHeight + depthMax`）。地形なし構成のため `estimateBaseHeight` の結果をそのまま使えば建物と整合する。
- ハザードラスタの地図オーバーレイはR1のF1-3と役割が被るため**R2では実装しない**。

## 11. 実装記録（2026-07-28、R1実装済みのmainへ統合）

計画どおり P0〜P5 を実装した。計画書との差分・実装中に判明したことは以下。

### 計画からの変更点

| 項目 | 計画 | 実装 | 理由 |
|---|---|---|---|
| `distanceMeters` の置き場所 | tilemath.js に新規追加 | tilemath.js に Haversine を実装し、R1で既に `js/compare.js` にあった平面近似版をそのラッパに変更 | R1が先にマージ済みで同名関数が存在したため。重複実装を作らない |
| `classifyFloodL1Color` | 計画に明記なし | `classifyFloodColor(rgba, legend)` に凡例テーブル引数を足し、L1用の薄いラッパを追加 | 既存の `classifyFloodColor` のシグネチャを壊さずL1を足せる |

| 地面高さ | `estimateBaseHeight` をそのまま使う | `resolveBaseHeight()` を追加し、1m以下なら `DEFAULT_BASE_HEIGHT`(35m) にフォールバック | 下記「実装中に判明したこと」参照 |

| e2eのカード内ボタン操作 | - | `page.click` ではなく DOM の `click()` を直接呼ぶヘルパを追加 | SwiftShader環境でCesiumの再描画により Playwright の actionability（stable）判定がタイムアウトするため |

### 実装中に判明したこと

- **水面が地下に沈む問題**: 建物タイルが未読込の地点では `scene.sampleHeightMostDetailed` が楕円体（実測 -0.0175m）を返す。PLATEAUの建物は実標高（中野区は概ね30〜60m）に置かれるため、この値をそのまま `EllipseGraphics.height` に使うと水面が建物の30m以上下に描かれる。`js/floodviz.js` の `resolveBaseHeight()` で 1m 以下なら既定値に寄せるようにした（`MIN_PLAUSIBLE_BASE_HEIGHT`）。単体テストで実測値 -0.0175 を回帰として固定した。
- **L1新凡例の公式凡例画像はL2と同じ** `img/shinsui_legend3.png`。デコードして8段（〜0.3m / 〜0.5m / 0.5m〜1m / 0.5m〜3m / 3m〜5m / 5m〜10m / 10m〜20m / 20m〜）であることを確認。細分2色は既存6色の**追加**であって置き換えではない（§3.1の想定どおり）。
- **公式のデータ名称**は「洪水浸水想定区域（計画規模（現在の凡例））」。
- 避難所CSVの列名は3種で全く異なる（`避難所名称` / `名称` / `NAME`）ため、`tools/fetch-shelters.mjs` の `SOURCES` に列名を定数化した。列名が変わると全件除外＋警告になり、既存GeoJSONは上書きされない。

### 既知の制限

- 浸水深3Dの地面高さは、建物タイル未読込時は既定値35mになる（実測値が取れていればそちらを使う）。§7の「±2m程度は目安として許容」の範囲を超えることがあるが、カード上で「目安」と明示している。
- 最寄り避難所は直線距離のみ（経路距離・徒歩分数は§9のスコープ外）。
- 内水氾濫は注記のみ（§2.2）。
- 共有URL・比較表にはR2の防災項目を載せていない（§9のスコープ外）。
