## 1. 機能要件と受け入れ基準

### F1-1. 共有URL（診断パーマリンク）

**仕様**
- URLハッシュに診断状態を保存する。形式は `URLSearchParams` 互換:
  `#v=1&spot={lon},{lat}&addr={URLエンコード住所}&cam={lon},{lat},{height},{heading},{pitch}&ov={overlay名}`
  - `v=1` はスキーマバージョン（将来の互換用、必須）
  - `spot` は小数6桁に丸める（約0.1m精度で十分・URL短縮）
  - `cam` は診断時ではなく**コピー時点**のカメラ（見ていた画角を再現するため）。height/heading/pitchは整数丸め
  - `addr` は検索経由の場合のみ（クリック診断では省略）
  - `ov` はF1-3のオーバーレイ表示状態（`use`/`fire`/`height`、カンマ区切り、非表示なら省略）
- 診断カードのヘッダ横に「🔗 リンクをコピー」ボタン。押下で現在状態をハッシュに書き込み（`history.replaceState`、履歴を汚さない）、URL全体を `navigator.clipboard.writeText`。成功で「コピーしました」トースト（2秒）。clipboard API不可時（非HTTPS等）は `prompt()` フォールバック
- ページ読込時にハッシュがあれば: `cam`へ`setView`（flyToではなく即時）→ `ov`のオーバーレイON → `spot`で自動診断。ハッシュ解析失敗は黙って無視（コンソールwarnのみ）
- **`spot`等の値は必ず数値検証してから使う**（NaN/範囲外(日本域外: lon 122〜154, lat 20〜46)は無視）。`addr`は`escapeHtml`を通してからDOMへ

**モジュール**: 新規 `js/share.js` — 純粋関数 `serializeState(state) => string` / `parseHash(hashString) => state|null`（DOM・Cesium非依存、Node単体テスト対象）+ `initShare(ctx)`（ボタン配線・起動時復元）

**受け入れ基準**
- 単体: serialize→parseの往復一致、丸め、異常系（壊れたハッシュ、範囲外座標、未知バージョン`v=9`→null）で12項目以上
- e2e: 弥生町を検索診断→コピー→そのURLで新規ページを開くと、同じ住所表示・同じ浸水ランクのカードが自動で開き、カメラ位置が復元される（座標±1e-4で照合）

### F1-2. 地点比較（最大3地点）

**仕様**
- カードヘッダに「⚖ 比較に追加」ボタン。押すと現在の`lastResult`スナップショット（座標・住所・洪水ランク・土砂3種の最悪値・用途地域/建蔽/容積/防火/高度・日照3値（計算済みなら）・建物の計測高さ（あれば））を`sessionStorage['karte-compare']`（JSON配列）へ追加
- 2件以上で画面下部に比較バー（「比較中: 2地点 [表を表示]」）。「表を表示」で比較モーダル（全画面オーバーレイ、`role="dialog"`）: 行=診断項目、列=地点（最大3列）。列ヘッダに住所（無ければ座標）と「×削除」「📍地図で表示」（flyTo+再診断）
- 日照が未計算の地点は「未計算」表示（比較モーダルからは再計算しない。地図で表示→カードから計算する導線の説明文を出す）
- 4件目の追加は最古を押し出す（その旨トースト）。同一地点（距離<10m）の重複追加は無視してトースト
- 比較状態の共有URL: `#v=1&compare={lon},{lat}[;{lon},{lat}...]`。開くと各地点を順に自動診断して比較モーダルを開く（日照はスキップし「未計算」。3地点の逐次診断で30秒超えないこと）
- ハザード値の表示色はカードと同じ`FLOOD_COLORS`等を流用

**モジュール**: 新規 `js/compare.js`（状態管理+モーダルDOM）。`diagnose.js`からは`lastResult`を受け取るのみ（依存方向: compare → diagnoseの公開関数。diagnose.jsへの逆依存を作らない）

**受け入れ基準**
- e2e: 弥生町と鷺宮を順に診断して比較追加→表に「0.5m未満 vs 区域外」「近隣商業地域 vs 第1種低層住居専用地域」が並ぶ。列削除・4件目押し出しも検証
- 比較URLを開いて2列のモーダルが自動表示される

### F1-3. 用途地域カラーオーバーレイ

**仕様**
- 左パネルに新セクション「都市計画レイヤー」: 「用途地域」「防火・準防火地域」「高度地区」の3トグル（初期OFF）＋透明度スライダー（30〜80%、初期55%）
- 実装は**自前ImageryProvider**（新規 `js/zoning-overlay.js`）:
  - `WebMercatorTilingScheme`、`tileWidth/Height=256`、`minimumLevel=14`、`maximumLevel=16`（z>16はCesiumが16を拡大表示する）、`rectangle`は中野区周辺に限定（`config.js`に `AREA_RECT = {west:139.60, south:35.66, east:139.72, north:35.75}` を追加。R4で自治体別に差し替える前提のコメントを書く）
  - `requestImage(x,y,level)`: 既存`zoning.js`の`loadMvtLib()`とタイルfetch（**MVTのArrayBufferキャッシュをzoning.jsから共用にリファクタして二重取得を防ぐ**）→ OffscreenCanvas（無ければcanvas）256×256にポリゴン描画して返す。404/空タイルは透明canvas。デコード失敗はエラーを投げずに透明を返しconsole.warn
  - Cesium 1.130のImageryProviderインターフェース準拠が必要（`errorEvent`, `credit`, `hasAlphaChannel=true`, `pickFeatures`はundefined返し等）。**実装冒頭でCesium公式ref-docのカスタムプロバイダ要件を確認し、不足プロパティによる実行時エラーをe2eで検出すること**
- 用途地域の配色（都市計画図の慣用配色に準拠。`config.js`に`USE_DISTRICT_COLORS`として定義、凡例と単一ソース）:

- 透明度スライダーで`ImageryLayer.alpha`が変わる。OFFでレイヤーが除去される
- 既存の点判定（診断カードの都市計画セクション）が回帰しない

### F1-4. UX改善バンドル

1. **検索キーボード操作**: 候補リストを↑↓で選択（`aria-activedescendant`更新）、Enter確定、Esc閉じ。入力欄に`role="combobox"`/リストに`role="listbox"`
2. **カードのセクション折りたたみ**: 各`diag-sec`のh3クリックで開閉（`aria-expanded`）。状態は`sessionStorage`に記憶
3. **診断履歴**: 直近5件（住所or座標+時刻）を`sessionStorage`に保存。検索ボックスのフォーカス時に入力が空なら履歴をドロップダウン表示、クリックで再診断
4. **現在地診断**: 検索バーに「📍」ボタン。`navigator.geolocation.getCurrentPosition`→診断。拒否/タイムアウト(10s)/非対応each専用メッセージ。**中野区外（AREA_RECT外）の場合**は「対応エリア外です（建物3Dは中野区のみ）」と表示しつつハザード・都市計画の診断は実行する（タイルは全国分あるため。日照と建物セクションは「エリア外」表示）
5. **a11y最低限**: 診断カードのルートに`aria-live="polite"`、モーダルのフォーカストラップ、全ボタンに`aria-label`、バッジ色のコントラスト確認（文字色#1a2028を維持）

**受け入れ基準**: e2e: キーボードだけで検索→候補選択→診断が完走。履歴から再診断できる。現在地はPlaywrightの`context.setGeolocation`（中野駅座標と、エリア外=新宿駅座標の2ケース）で検証

### F1-5. CI導入（R6から前倒し）

- `.github/workflows/ci.yml`: push/PR時に Node 22 で `npm ci && npm run test:unit`。単体はネットワークを使うテスト（実タイル照合）を含むため、**`SKIP_NETWORK=1`で実タイル照合をスキップするフラグをテスト側に追加**し、CIはフラグ付きで実行（GitHub Actionsからは外部取得可能だが、外部サーバ都合でCIが赤くなるのを避ける）。週1のscheduleでフラグ無し（実タイル照合込み）も実行し、失敗時はissue自動起票（`actions/github-script`）
- e2eはCIに含めない（Chromium+外部データで不安定要因が多い）。代わりに`workflow_dispatch`で手動実行できるjobを用意（GitHub Actionsランナーでは中継不要のため`HARNESS_DIRECT=1`で直接fetchするモードを`test/harness.mjs`に追加）

**受け入れ基準**: ローカルで `SKIP_NETWORK=1 npm run test:unit` が外部アクセスなしでパス。ci.ymlがpush時にグリーン（実装完了後、push後に確認）

## 4. リスクと対策

| リスク | 対策 |
|---|---|
| カスタムImageryProviderがCesium 1.130の内部要件を満たさず実行時エラー | P2の最初に最小プロバイダ（全タイル単色半透明）でe2e起動確認してからMVT描画を実装する2段構え |
| MVT描画の座標変換ミス（extent 65536→256px、タイル境界のポリゴンクリップ） | vector-tileの`feature.loadGeometry()`はタイル座標で返るので `px = v/extent*256` の線形変換のみ。境界クリップはcanvasのクリッピングに任せる（描画は`beginPath`で全リング、`fill('evenodd')`）。単体でoverlay描画関数（canvas非依存のパス生成部）をテスト |
| クリップボードAPIがe2e(headless)で不安定 | Playwrightの`grantPermissions(['clipboard-read','clipboard-write'])`を使用。それでも失敗する場合はハッシュ文字列の内容検証に切り替え（コピーの成否ではなく`location.hash`を検証） |
| sessionStorageがプライベートモード等で例外 | try/catchでラップし、失敗時は機能を静かに無効化（診断本体には影響させない） |
| 比較URLの逐次診断が遅い | 日照スキップ+ハザード/都市計画は並列実行（既存диagnoseは項目並列なので地点も2並列まで並行） |
| オーバーレイとGSI背景の重なりで視認性低下 | 透明度スライダー（初期55%）と、オーバーレイON時に背景を淡色地図へ切替提案するヒント表示 |
