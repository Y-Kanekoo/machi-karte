# 中野区 3D都市モデルビューア + 街カルテ（nakano-3d）

東京都中野区全域を3Dで表示するWebアプリです。国土交通省 [Project PLATEAU](https://www.mlit.go.jp/plateau/) の中野区 3D都市モデル（2025年度版）をストリーミング配信で読み込み、CesiumJSで描画します。ビルドや3Dデータのダウンロードは不要で、`index.html` を開くだけで動きます。

住所を入力するか地図をクリックすると、その地点の **洪水浸水想定・土砂災害警戒区域・用途地域・日照時間** をまとめた「**街カルテ**」を表示します。診断結果は **URLで共有**でき、**最大3地点を並べて比較**したり、**用途地域を地図に色分け表示**したりできます。

## デモ

GitHub Pages: https://y-kanekoo.github.io/nakano-3d/

**初回のみ有効化が必要です**（GitHub Actionsのトークンでは自動有効化できないため）:

1. リポジトリの **Settings → Pages** を開く
2. 「Build and deployment」の **Source** を **GitHub Actions** にする
3. **Actions** タブから「Deploy to GitHub Pages」ワークフローを **Re-run**（または何かをpush）

以降はmainへのpushごとに自動デプロイされます。

## 機能

### 街カルテ（地点診断）

画面上部の検索ボックスに住所を入れるか、左パネルの「地点を診断」をONにして地図をクリックすると、その地点の診断カードが開きます。建物をクリックした場合は建物属性も一緒に表示されます。

| セクション | 内容 | データ元 |
|---|---|---|
| 📍 地点 | 住所（検索時）と経緯度 | 国土地理院 住所検索API |
| 🌊 洪水浸水想定 | 想定最大規模の浸水深ランク（区域外 / 0.5m未満 / 0.5〜3.0m / … / 20.0m以上）／**浸水継続時間**（12時間未満〜4週間以上）／**計画規模の想定**／**浸水深の3D表示** | ハザードマップポータル |
| ⛰️ 土砂災害警戒区域 | 土石流・急傾斜地の崩壊・地すべりの3種を、区域外 / 警戒区域（イエロー）/ 特別警戒区域（レッド）で判定 | ハザードマップポータル |
| 🏫 避難所 | 最寄りの震災時避難所・水害時避難所（名称と直線距離） | 中野区オープンデータ（同梱GeoJSON） |
| 🏘️ 都市計画 | 用途地域・建蔽率・容積率・敷地面積の最低限度・防火地域・高度地区 | PLATEAU 都市計画決定情報（MVT） |
| ☀️ 日照 | 冬至・春分・夏至それぞれの日照時間（7:00〜17:00 JST）と時刻帯の横棒タイムライン。視点高さセレクタで一般地点は1〜15階、建物は各階・屋上の日照を再計算 | 建物3D Tilesへのレイキャスト＋NOAAの太陽位置計算 |
| 🏢 建物 | 計測高さ・用途・階数などのCityGML属性（建物クリック時のみ） | PLATEAU 建築物モデル |

各項目は独立して非同期に取得され、取得でき次第カードに埋まります。1つの項目が失敗しても他の項目には影響しません。

判定のしくみ:

- **洪水・土砂災害** — 該当地点のラスタタイル（z=16 PNG）を1枚取得し、canvasで地点ピクセルの色を読んで凡例色と照合します（最近傍色。距離が離れすぎる場合は「判定不能」）。透明ピクセルとタイル404は区域外です。
- **都市計画** — PLATEAUのベクトルタイル（MVT, z=16）を取得・デコードし、点内包判定（ray-casting・偶奇規則）で該当ポリゴンの属性を読みます。区境をまたぐ地点でも正しく判定できるよう、タイルに含まれる隣接区のポリゴンも除外していません。
- **日照** — 選択した視点高さから太陽方向へレイを飛ばし、`scene.pickFromRay` で建物との交差を調べます（1日31サンプル×3日＝93レイ）。一般地点は1〜15階、建物クリック時は各階と屋上を選択でき、変更すると日照だけを再計算します。計算前にはカメラを動かさず、太陽経路に沿って周辺の建物タイルをwarm-upします。
- **日影マップ** — 画面中心200m四方を40m→20m→10mの順で段階的に計算し、冬至・春分・夏至の日照時間を地表へ色分け表示します。左パネルで日付と10m／20mピッチを選び、「計算する」を押します。進捗表示中も地図を操作でき、「中断」で部分結果を残すか「クリア」で表示を消せます。

**表示される値は公的機関の公開データをそのまま判定した結果**であり、法的な効力はありません。正式な情報は各自治体の窓口・公式図面でご確認ください。

### 日照・日影の前提と限界

- 地形起伏は考慮せず、地球楕円体を地表として扱います。神田川の谷から台地までの高低差（約20m）は、計算地点の地盤高で近似するのみです。
- 樹木・フェンス・電柱など、3D都市モデルに含まれない遮蔽物は考慮しません。
- 中野区の3D都市モデルだけを読み込むため、区外（新宿区・渋谷区など）の建物がつくる影は考慮しません。中野坂上・東中野などの区境付近では、日照を実際より多く見積もる可能性があります。
- 太陽経路のwarm-upで未読込タイルの影響を軽減しますが、建物の見落としがゼロになる保証はありません。
- 日照時間と日影マップは参考情報です。建築基準法の日影規制の検討や、宅地建物取引業法に基づく重要事項説明には使用できません。

### 防災（浸水継続時間・避難所・浸水深3D）

- **浸水継続時間** — 想定最大規模の洪水で浸水が引くまでのおおよその目安を7段階（12時間未満／12時間〜1日／1日〜3日／3日〜1週間／1週間〜2週間／2週間〜4週間／4週間以上）で表示します。**「透明＝浸水しない」ではない**点に注意が必要なので、洪水ランクが「区域外」なら `―`、浸水想定区域内なのに継続時間の配信がなければ「データなし」と明確に出し分けています（中野区では弥生町・本町が後者にあたります）。凡例上「2週間〜4週間」の色は自治体により「2週間以上」を意味することがあるため、その色が出たときだけ注記を添えます。
- **計画規模の想定** — おおむね30〜100年に1回程度の降雨による浸水想定（`01_flood_l1_shinsuishin_newlegend_data`）です。新凡例は既存6色に細分の2色（〜0.3m / 0.5〜1.0m）を加えた8色構成なので、想定最大規模とは別の凡例テーブル（`FLOOD_LEGEND_L1`）で判定しています。
- **内水（雨水出水）** — 中野区分は重ねるハザードマップに配信がなく（掲載市町村一覧に中野区なし。東京都は昭島市・福生市のみ）、本ツールは未対応です。カードから[中野区ハザードマップ](https://www.city.tokyo-nakano.lg.jp/bosai/hazardmap/hazardmap.html)へ案内しています。将来配信が始まれば `HAZARD_TILES` に1エントリ追加するだけで対応できます。
- **避難所・避難場所** — 中野区オープンデータ102件（震災時45・水害時44・広域13）を `data/shelters.geojson` として同梱し、左パネルのトグルで種別色分け（緑=震災時 / 青=水害時 / 橙=広域）のピンを地図に表示します。ラベルは2.5km以内でのみ表示して重なりを抑えています。診断カードには最寄りの震災時・水害時避難所を1件ずつ、Haversineの直線距離で表示します（経路距離ではありません）。
- **浸水深の3D表示** — 「💧 浸水深を3Dで表示」で、診断地点の周囲150mに想定浸水深の上限ぶんの半透明の水面（`EllipseGraphics`）を立ち上げます。左パネルの洪水レイヤー（PLATEAU）が区全域の想定を面で見せるのに対し、こちらは1地点の深さを柱状に見せる目安です。「20.0m以上」は20mでキャップします。区域外・判定不能ではボタンが無効になり、カードを閉じるか別地点を診断すると水面は消えます。

### 共有・比較・見える化

- **🔗 リンクをコピー** — 診断カードのヘッダから、いま見ている診断結果（地点・住所・カメラ画角・表示中の都市計画レイヤー）をURLハッシュに載せてコピーします。そのURLを開くと同じ画角・同じ地点の診断が自動で復元されます。形式は `#v=1&spot={lon},{lat}&addr=...&cam={lon},{lat},{height},{heading},{pitch}&ov=use,fire`。壊れたURLや日本国外の座標は黙って無視されます。
- **⚖ 比較に追加** — 最大3地点までスナップショットを貯め、画面下部の比較バーから比較表（洪水・土砂・用途地域・建蔽率・容積率・防火・高度地区・日照3値・建物高さ）を開きます。列ごとに「📍 地図で表示」「× 削除」ができ、比較状態も `#v=1&compare={lon},{lat};...` でURL共有できます（復元時は日照をスキップして「未計算」と表示します）。
- **都市計画レイヤー** — 左パネルから「用途地域」「防火・準防火地域」「高度地区」を地図に色分け表示できます。透明度は30〜80%で調整できます（初期55%）。PLATEAUのベクトルタイルをブラウザ内でcanvasにラスタライズする自前の `ImageryProvider` で描画しており、点診断とタイルのキャッシュを共用しています。配色は都市計画図の慣用配色に準拠し、右下の凡例と同じ定義（`js/config.js` の `USE_DISTRICT_COLORS`）を使っています。
- **UX** — 検索候補のキーボード操作（↑↓/Enter/Esc）、診断カードのセクション折りたたみ、直近5件の診断履歴、「📍 現在地を診断」に対応しています。対応エリア（中野区周辺）の外では建物3Dと日照が使えないため、その旨を表示したうえでハザードと都市計画のみ診断します。

### 3Dビューア

- **建物モデルの切り替え** — LOD2（テクスチャ付き・高精細）/ LOD2（テクスチャなし）/ LOD1（箱型・軽量）
- **高さによる色分け** — 建物の計測高さで5段階に色分け
- **影シミュレーション** — 影の表示と時刻スライダー（6:00〜18:00 JST）
- **日影マップ** — 画面中心200m四方の冬至・春分・夏至の日照時間を10m／20mピッチで色分け。粗い40mブロックから段階的に精細化し、進捗表示・中断・クリアに対応
- **防災レイヤー** — 洪水浸水想定区域（神田川流域・荒川水系）を半透明で重ね合わせ／避難所・避難場所（102件・種別色分け）
- **道路（LOD3）・水部レイヤー**
- **スポット移動** — 中野駅、サンプラザ跡・四季の森公園、中野ブロードウェイ、新井薬師、哲学堂公園
- **背景地図切り替え** — 地理院の航空写真 / 淡色地図（都市計画レイヤーは背景を切り替えても残ります）

## ローカルでの実行

静的サイトなので、そのままHTTPサーバで配信するだけです（アプリ本体にビルド・npm依存はありません）。

```bash
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

## テスト

テストのみnpm依存があります（アプリ本体は無依存のまま）。単体352項目 / スモーク17項目 / e2e 213項目（`e2e.test.mjs` 90 + `e2e-r1.test.mjs` 123）。

```bash
npm install

# 単体テスト（ブラウザ不要）: 太陽位置計算・タイル座標変換・ハザード判定・共有URL・比較・オーバーレイ
npm run test:unit

# 外部データを一切取りに行かない単体テスト（CIと同じ条件）
SKIP_NETWORK=1 npm run test:unit

# スモーク + e2e（Playwright + Chromium が必要。別ターミナルで python3 -m http.server 8123 を起動しておく）
npm run test:smoke
npm run test:e2e

npm run expectations

# 避難所GeoJSONを中野区オープンデータから再生成する（出典URLが変わったとき等）
npm run shelters
```

### 同梱データについて（避難所・避難場所）

`data/shelters.geojson` はこのリポジトリで唯一の同梱データです。防災情報は外部サービスの停止時にも表示できるべきであること、wagmapのリソースURLがID直打ちで恒久性の保証がないことから同梱方式を採っています。

| 元データ | 件数 | リソースURL |
|---|---|---|
| 震災時の避難所一覧 | 45 | `https://www2.wagmap.jp/nakanodatamap/nakanodatamap/opendatafile/map_32/CSV/opendata_5000342.csv` |
| 水害時避難所 | 44 | `https://www2.wagmap.jp/nakanodatamap/nakanodatamap/opendatafile/map_28/CSV/opendata_18000130.csv` |
| 広域避難場所 | 13 | `https://www2.wagmap.jp/nakanodatamap/nakanodatamap/opendatafile/map_32/CSV/opendata_6000680.csv` |

- 出典: 中野区オープンデータ（[東京都オープンデータカタログサイト](https://catalog.data.metro.tokyo.lg.jp/)経由）／ライセンス: [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.ja)（CKAN APIの `license_id` で確認）

## CI

`.github/workflows/ci.yml`:

- **push / PR** — Node 22 で `npm ci && npm run test:unit`。外部データ取得を伴う実タイル照合は `SKIP_NETWORK=1` でスキップします（外部サーバの都合でCIが赤くならないように）。
- **週次（月曜 12:00 JST）** — `SKIP_NETWORK` なしで実タイル照合込みの単体テストを実行し、失敗したらissueを自動起票します（外部データの更新検知）。
- **手動実行（workflow_dispatch）** — Chromiumを入れてスモーク＋e2eも回します。GitHub Actionsのランナーは外部へ直接出られるので `HARNESS_DIRECT=1`（中継なし）で動きます。スクリーンショットはartifactとして残ります。
